# 前向点云与正常飞行停止门的独立诊断

2026-11-12。本次仅阅读生产源码、公开世界文件及既有本队证据，运行无 ROS、无网络的独立几何探针；未改生产、未上传、未访问裁判私有数据。**当前正常前飞被拒绝有确定的几何原因；把检查端盖改远只能绕开其中一个数值矛盾，不能证明近场扫掠体已被观测。**

## 1. 可复现的根因

`mission_node.py:48` 将传给净空门的距离固定为 `D=R+|v|×max(pose_timeout,scan_timeout)`。候选整机包络来自 `docs/candidates/uav_body_envelope_20261112.json`，没有修改水平外廓：

| 值 | 米 |
| --- | ---: |
| 含倾角与余量的水平半径 R | 0.485296542 |
| 原点下方 B | 0.120340689 |
| 原点上方 U | 0.218340689 |
| v=.2、timeout=.5 时真实 D | 0.585296542 |

公开固定版本世界 SHA256 `595cbb95a395a2ca8923b79a0a5d3523e9198711059307d8b8cde6d47f35c9c1` 第230–259行的前向雷达位于 `(0.12,0,0.18)`，垂直孔径±0.55rad，量程0.08–4m，121×21束、12Hz。生产候选采用水平πrad，保守小于 SDF 的3.1416rad。当前默认 profile 仍 `verified=false`，因此这些不是当前平台完整三维标定结果。

水平姿态下，端盖最下边相对雷达的俯角为：

`atan2(0.18+B, D-0.12) = 0.573192784rad > 0.55rad`。

故生产 `pointcloud_sensor_envelope_path_clear` 返回 false 是正确拒绝。要使同一端盖恰好进入垂直孔径，数学下界为：

`D_min = .12 + (.18+B)/tan(.55) = .609868104m`。

独立探针对该下界前后1μm分别得到拒绝／放行。73个倾转轴方向、倾角.05rad的离散检查中，最大所需端盖距离约 `.683788544m`；此离散最大值不是所有姿态的解析保证。**减速会让D更短，从而加剧该孔径拒绝；不能据此提高速度，因为速度只是在公式中意外扩大视锥检查距离。**

`D=R+v×age` 还只含陈旧度项，没有经实际减速响应验证的 `v²/(2a)` 或等价制动项。命名为 stop distance 不能当作已经量测的物理停距。

## 2. 为什么不能只把 D 改成1.2m

独立探针加入了一个明确反例：机体相对点 `(.52,0,-.11)`。

- 它位于当前整机前缘 `.4853m` 之外、真实所需检查距离 `.5853m` 之内，也位于上下包络内；向前平移后可能进入新的扫掠带。
- 雷达相对点为 `(.40,0,-.29)`，俯角约 `.6273rad`，超出±.55rad孔径。
- 将端盖改为1.2m后，真实生产函数对三个远端返回给出 true；即使额外提供这个孔径外点，函数按真实孔径过滤后仍给出 true。

这不是该函数偷偷承诺的全空间安全性：源码已标明它是 sampled stopping corridor。但它说明**不能把远端盖完整可见升级成从机体到端盖之间完整自由空间的证明**。该近场条带在当前时刻不可见；仅提高采样密度、缩小图像阈值、调整端盖或延长超时均不能产生不存在的观测。

探针：`runs/review/flight_fov_20261112/independent_probe.py`；完整参数、源码SHA、轴向网格及反例：同目录 `metrics.json`。运行命令：

```text
python runs/review/flight_fov_20261112/independent_probe.py
```

## 3. 与窗孔是否自相矛盾

候选窗口1m宽、净高.75m，本次不重新证明候选与当前平台完全相同。水平圆柱包络直径约 `.970593m`，中心横向容差 `.01m` 后只剩总计 `.009407m`、每侧 `.004703m`工程余量；默认 `.08m`容差应拒绝，已有补丁正确保留此行为。按候选穿窗高度 `.75m`，上下包络与 `.04m`高度容差可以装入 `.4–1.15m`窗口；所以**竖直尺寸分离已经消除了旧球模型的必然矛盾，但不代表实飞精度满足窗口，也不消除雷达近场盲区**。

同机体 `/scan` 是一层水平扫描，可能补充当前高度的侧后方障碍；下视三束只能补中心下方距离。二者都不能独自填满前下方／上方三维扫掠体。窗框匹配、候选静态几何及真实曝光pose可以提供限定的窗口几何假设，不能标成当前未知动态障碍均可见。

## 4. 最小可验证的后续方案

保持现通用门拒绝未知空间。不要为了当前完整mission放行而先删掉FOV门、改小旋翼尺寸或把D直接写成1.2。沿既有有限起飞实验路线，分两层补证据：

1. **有限响应层。** 先完成现正Z、归零后的真实高度轨迹；下一次受限动作再测下降及水平响应／真实停距。继续依赖已明确声明的固定静态实验柱，记录与候选地图一致性，而不称全方向动态避障。
2. **限定航段层。** 在已经确认的静态飞行区域做短前进实验。把“实际停止所需距离”和“用于观测的前视距离”分开；当前帧的远端观测必须结合已建立的近场自由空间来源。近场来源可以是经当前几何核对的固定静态航段，或此前视角观测并带原始时间、完整pose、误差和寿命的空间记录。没有这些来源便保持拒绝。未知动态环境下还需合理的动态障碍速度／过期上界，不能仅凭缓存或候选地图宣称安全。
3. **组合门回归。** 使用真实tick速度、实际尺寸、实际传感器位姿、当前时间配对和已量测停距；覆盖孔径边界、近场盲区、.05倾角、窗框和观测过期。端盖、扫描、下视与静态航段每个证据来源应独立记录，任何一项失效归零。

当前缺的最小运行数据不是另一个开源算法，而是**完整原始前向点云及其配对pose／静态TF、在飞行高度收到的水平scan、指令与实际水平／Z响应以及实际归零停距**。v5仅存点云字节前缀，不能重建这些数据。现 `bounded_vertical_response.py` 主要存odom、scan、下视scan和TF，未采集完整前向点云；可以在后续独立只读采集版本补数据，不能把已有元数据称为完整三维净空证明。

有限飞行逐项通过后，再接窗口和定位后照射；前视识别与下视灯不能维持同一居中条件的问题仍按 `full_mission_bridge_20261112.md` 的分阶段方案处理。此报告没有取得新平台分数或证明完整任务可执行。
