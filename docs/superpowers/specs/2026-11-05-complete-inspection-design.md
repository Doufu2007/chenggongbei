# 全域巡检功能补全设计

用户目标：补全已报名的全域巡检任务代码；直接实施，不创建队伍、不付款、不消耗正式上传次数。

完整任务顺序：三个地面点按本轮公开任务顺序识别；地面车回指挥中心；无人机起飞；窗口1识别、明显下降、低高度穿越；两个空中点分别识别且稳定照射；窗口2识别、下降、穿越；回指挥中心后降落。到点不等于识别成功，输出识别不等于裁判确认。

采用 ROS2 Humble/Python/OpenCV。保留旧的轻量 FSM 作为历史单元，新增独立、无 ROS 依赖的完整 MissionController，ROS 节点调用同一控制器。视觉输出带目标身份、相机来源、原始时间和归一化图像坐标；二维码、ArUco、用户提供的参考图匹配均不得在失败时猜测。连续定稳必须在丢帧、漂移、失去照射或错误目标时清零。

场地地图必须来自队伍测量或官方公开场地资料，不能把本轮随机答案当地图。官方资料尚未给出灯光、识别上报、起降、速度消息类型、任务数据格式和坐标系。实现可验证的标准消息适配器和显式映射配置，未配置时报告阻塞，不向猜测接口发送控制命令。禁止读取仿真真值、原始裁判事件、随机结果文件。

实现边界：根代理负责 ROS 适配、配置、启动与交付；子代理负责纯任务闭环与视觉/几何；独立代理复核官方接口证据。所有假场景仅在 tests/tools 内，不能作为正式默认任务。

验收：纯控制器在运动学模拟中必须按正确顺序完成每项动作；负例覆盖错目标/旧图/地空混用/窗口不下降/低于空中高度/漂移/灯光无反馈/失去里程计/障碍阻塞/超时；视觉用真实 OpenCV 合成图和投影数据；尝试使用真实 ROS2 运行节点，条件不足需明示；构建 ZIP 与启动脚本，但不宣称平台已通过。
