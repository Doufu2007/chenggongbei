# 三地面点连续任务：候选走廊与交接接口

2026-11-12。**只读离线设计，未修改v25或任何生产源码，未接ROS、未上传。** 本设计以公开候选墙／窗几何、0.447m全机保守半径及含轮底盘外廓为依据；不读取类别分配或隐藏裁判。全部5选3有序组合共60种，均已枚举。首点真实得分不等于这些连续路线已被平台验证。

推荐基线保留ground_0现有轴线进入段，其余采用下面的候选分支。60种顺序名义几何全部通过原 **0.641m完整环扫门**，最长全程 **11.114290m**、累计计划转角 **23.304867rad**。加入每点0.30m／0.40rad工程余量后为 **12.014290m／24.504867rad**；建议下一版本在起步前明确冻结全程cap **12.5m／25rad**，绝不能靠换点清零实现。它们是本队工程预算，不是官方规则。

## 走廊图和少航点连接

采用x=0.6的竖直公共脊线，换点过程中使用y∈[−2.69,−0.10]的部分。每次从已入区的实际末pose出发：先水平回到(0.6,实际y)，再沿脊线到下一观察行；只有ground_4再向西0.25m。因此从任一末点到下一点外观察位最多3条直线／2个中间航点。所有转向独立停稳，禁止把它们当弯曲直行轨迹。

| ID | 候选观察位xy／观察yaw(rad) | 观察后进入航点 | 声明前目标末yaw |
|---|---|---|---|
| ground_0 | (.6,−.45)／−1.042722 | (.6,−1.35)→(1.115,−1.35)，保留现轴线 | 0，东向 |
| ground_1 | (.6,−.5)／−2.185459 | 直达(0,−1.35) | π，西向 |
| ground_2 | (.6,−1.8)／−2.158799 | (.6,−2.62)→(0,−2.69) | π，西向 |
| ground_3 | (.6,−1.025)／−1.042722 | 直达(1.115,−1.925) | −π/2，南向 |
| ground_4 | **(.35,−.10)／−.716542** | 直达(1.115,−.775) | −π/2，南向 |

首次起点名义(0,0,0)：ground_0～3仍先向东到(.6,0)再向南；ground_4直接走到(.35,−.10)。此后不再返回原点，也不再要求上一点末pose为近零yaw。

ground_4原观察位(.35,0)适合从原点水平接近，却不能在换点时从南向北直达：laser前移0.08m使终点到北墙仅0.57m，原门必拒。设计将观察位南移0.10m；原800×800、原K与候选外参下四角bbox约x=[134.89,642.39]、y=[485.59,669.74]，全部在图内。这里只预测可见性，下一局仍须从真实图识别与关联，未改matcher或认可该图已存在。其余四个观察位／朝向保持现候选值。

## 必须显式执行的转向角锚

现route `_start_turn`按`atan2(destination-current)`产生朝向，忽略segment.heading；零长度腿还会触发`route_leg_too_short_or_behind`。现single_point末腿直接转入DECLARE_WAIT，也不会执行最终yaw。**不能把本表末yaw或零长度waypoint交给现接口并宣称已经对齐。** 下一实现需要单独的TURN_ONLY操作与其静稳交接。

关键反例是ground_2脱离。它在(0,−2.69)西向时，去脊线需要改为东向。若把−π→0的默认最短角选成经南半圆，laser最低到y=−2.77，到南墙仅 **0.58m**。安全角锚必须走北半圆：

```text
若起始yaw=+π： +π → +π/2 → 0
若起始yaw=−π： −π → −3π/2 → −2π  （物理朝向同西→北→东）
每个箭头均TURN_ONLY、零平移、停稳；然后朝东DRIVE_TO_XY(.6,−2.69)。
```

不能仅靠规范化角的正负选择方向。参考规划器对两条完整转向圆弧分别算0.641m门，选择通过的较短弧；再拆成每段≤π/2的角锚。当前2cm南向末位误差的可复现拒绝也保留：pose=(0,−2.71,−π)时laser距南墙0.64m，无安全起始弧，参考接口拒绝出计划，不尝试“绕过去”。

进入末腿与最终对齐的名义锚如下。先DRIVE_SETTLE，再TURN_ONLY，最后TURN_SETTLE；静稳与停车锚不能跨运动保留。

| 点 | 末直行yaw→最终yaw | 显式最后转向 |
|---|---|---:|
| ground_0基线 | 0→0 | 无额外转向，但仍需末腿静稳 |
| ground_1 | −2.185459→−π | CW 0.956133rad |
| ground_2 | −3.025451→−π | CW 0.116142rad |
| ground_3 | −1.051052→−π/2 | CW 0.519744rad |
| ground_4 | −0.722979→−π/2 | CW 0.847817rad |

参考操作同时保留`expected_start_yaw_rad`、`signed_subturn_rad`、规范化`target_yaw_rad`、列表内连续坐标`target_yaw_unwrapped_rad`及CW/CCW方向。连续角的坐标范围明确限于本操作列表，不将两个独立列表的数值当全局累计转角；全局累计转角仍由真实odom绝对增量产生。执行前须核当前yaw与该子操作起点相容，绝不能从一个−2π数字直接跳算到下一规范化+π/2。

## 60种顺序的精确预算

| 核算项 | 保留ground_0轴线的推荐基线 |
|---|---:|
| 完整顺序数量 | 60，另保留5条首段与20条有向换点连接 |
| 最长三点名义路径 | **11.114290097m** |
| 对应顺序 | ground_2→ground_0→ground_4 |
| 加每点0.30m余量 | **12.014290097m** |
| 最大累计计划转角 | **23.304866761rad**，同一顺序 |
| 加每点0.40rad余量 | **24.504866761rad** |
| 最长一次“上一末点→下一观察→下一进入末点” | **4.460220564m**，ground_2→ground_4 |
| 其中到下一观察位的最长距离 | **3.44m**，ground_2→ground_4 |
| 最长连续直行腿 | **2.59m**，脊线从y=−2.69到−0.10 |
| 未分解的最大单次转角 | π；输出均已拆成≤π/2的TURN_ONLY |
| 三点最多直行腿／转向子操作 | 12／20 |
| 最大距永久起点位移 | **2.756102320m**；加0.15m为2.906102320m |
| 全程laser最小距离／相对门余量 | **0.650000m／9mm** |

最长完整换点本身已超过4.2m，因此4.2m也不能当每次换点的通用cap。这里12.5m是一次完整三地面点任务的全程cap；每段剩余额度从同一账本扣减。起点位移与累计路径不同，不能用尚未超过3m起点半径证明已走路径不超预算。

还核算了ground_0也改为直达斜腿的减路程备选：60顺序最大路径10.774722699m，另一个顺序取得最大转角22.265378360rad，不能把两者混称来自同一顺序。加入余量分别11.674722699m／23.465378360rad。此备选改变已真实得分点的进入段，推荐首版保留轴线基线。

以上是几何距离和角度预算，没有假定执行器单位增益。现300s总墙钟／100s累计转向时间不能不加核对地套到约23.3rad的三点任务；每次分角锚可重新拥有局部45s计时，但**累计转向时间和全程起始墙钟不得重置**。新时间cap须依据v25实际响应预先配置，不能用`距离/.1`或`角度/.5`冒充保证，也不能因临时超时而边走边延长。

## 外廓与真实跟踪误差

候选base盒0.34×0.22m；含四轮地面碰撞并集约0.35×0.31500033m。表中末姿态均可名义完整容纳含轮底盘：ground_0／1按2cm平移与0.025rad最终yaw误差包络仍余18.1747mm，ground_2／3／4仍余8.1747mm。g3／4必须执行南向最后对齐，不能复用东向末腿的15mm名义边距来承诺完整底盘。

全机旋翼外廓任意yaw下的单轴投影最少0.67m，目标区域最大边0.55m，故仍不声称全机完全进入。0.447m半径、传感器偏置上界和原环扫安全量均未缩小。

**名义覆盖60种顺序，不代表允许范围内的任意跟踪误差都能完成。** 起点北墙／ground_2南向接近拐点的9mm环扫余量小于2cm跟踪容差。ground_2出发环扫名义最小0.66m，南偏2cm后成为0.64m，现门正确拒绝。实时scan必须在其原时效内决定能否继续；不能用离线通过覆盖坏scan，不允许通过改小机体或放宽门追求全60完成率。下一版本可先在真实执行中只完成当时有有效门的顺序，拒绝结果要如实保留。

## 初版单点为何不能直接反复调用

1. `plan_ground_observation_route`显式要求初始xy距原点≤0.05m、yaw≤0.05rad。上一点末pose不满足，不能平移／重命名odom去蒙混该合同。
2. 首次WAIT启动会建立`global_origin`、`previous_path_xyz`、`previous_yaw`等；新建三个guard会丢全程累计。复用旧guard又会遇到STOP／FINISHED终态、旧target／识别／发送锁存，不能强行复活。
3. 现3m／6rad和单点时间预算不足；首段索引／末腿到DECLARE的短路也没有下一点移交语义。
4. 零长度腿不支持turn-only，heading字段不等于已执行。末姿态与ground_2北半圆必须由新操作明确落地。

## 可执行的参考接口与最小账本交接

纯分析脚本已提供数据接口，可供实现者移植；它不导入ROS、控制状态机或感知模块：

```python
plan_transfer_from_pose(previous_id, next_id, actual_pose,
                        scheme="preserve_ground0_axis") -> dict
# actual_pose = (真实x, 真实y, 真实yaw)，不冒充原点。
# 返回 to_observation_operations、entry_operations_after_current_visual_report，
# 以及路径/角度/圆弧净空诊断。候选弧或直线不过.641即拒绝。
# 两段之间必须执行当前目标的真实图像识别、唯一上报与现有门。
```

实际实现需要把它变成独立的全程mission执行器或向现guard注入共享账本；不能直接import含本机分析路径依赖的脚本上线。最小交接如下：

- 全程只初始化一次：真实`mission_origin`、`started_wall_s`、不可变`draw`、累计path、累计绝对rotation、previous真实pose/yaw、累计drive／turn墙钟和全程caps。切目标不清、不回滚、不扩大这些量。
- 每段可重建：局部drive／turn原点、该操作起始墙钟、waypoint索引、静稳anchor与停止路径锚；但父账本继续计入所有停止漂移和原地转角。新规划的剩余距离加余量必须放得进已有剩余额度，否则停止。
- 每次目标移交先全零、原子锁存上一目标的单次recognition／declaration attempt，保持历史与实际回执原文；再推进不可变draw的索引。只以本目标当局图像决定本目标类别，不能把上目标的识别结果带过去。
- 运动前取消旧worker context，递增mission内单调stationary epoch，清旧capture／expected jobs／匹配结果／待发送recognition。全程session与job_seq继续；当前目标ID在该点内冻结。原抽签first ID保留为mission事实，不把可变任务表重新排序后覆盖它。
- 单点“transport完成”应成为父mission的一次有界交接事件，不先进入吸收STOP再修改状态复活。最后一点完成后才进入任务终止；真实官方计分是否接受仍按平台证据记录。
- 新操作状态至少区分TURN_ONLY→TURN_SETTLE、DRIVE→DRIVE_SETTLE、OBSERVE／RECOGNIZE／REPORT、FINAL_ALIGN→SETTLE→DECLARE、POINT_HANDOFF。原速度／雷达／时效、命令锁、UAV观测来源与曝光绑定继续执行，不由几何规划接管。
