# v21 路线横偏：独立只读复核

日期：2026-11-12。本报告读取原始 `callback_route_v21.jsonl`，在新目录调用既有 route analyzer，并按原实际发布/10Hz轨迹独立复算。未操作网站、改控制代码、改原raw、放宽保护或重标坐标。

## 确定发生的情况

本局公开首点 `ground_4`，候选规划单腿从近原点至 `(.35,-.05)m`，冻结直行朝向 `-.141935272rad`。v21 的原 `.35rad/s` 转向下限实际推动了初次转向；静稳后进入DRIVE，10Hz首帧 yaw=`-.117500100rad`，相对计划朝向残差 `+.024435172rad`，在该短腿 `.025rad` 接纳窗内。这个残差会花掉一部分横偏预算，但不足解释后来的全部横偏。

核心 `FINISHED`，reason=`approach_cross_track_limit`，elapsed=`12.7s`。全程resume0，无第二次重对准。实际发布首次 STOP在节点elapsed **10.643056s**；紧随其后的motion log使用原odom stamp `13.44s`，报告横偏触发而不是heading/倾角/时效/扫描故障。最终元数据投影 `.150708660m`、横偏 `+.020129416m`；该值是最终快照，不冒充精确触发帧。

## 初次转向残差、倾斜与惯性分别能解释多少

从精确drive_origin至最后一条STOP前10Hz轨迹（stamp13.42）重算：位移 `(dx=.150339414,dy=-.001379818)m`，净方向 `-.009177758rad`，横偏 **.019900949m**。若同样净距离完全沿DRIVE首样本机体yaw运动，初次转向残差只产生 **.003673359m** 横偏；剩余约 **.016227591m** 对应于位移方向与机体yaw不一致。这里是几何分解，不是拟合动力模型或精确因果归因。

中途停车校准实际完成，源码元数据stationary=`1.061690s`墙钟 / `1.04s`仿真；随后恢复高档仍持续同样方向差。恢复高档区间观察最大角速度 `.0013555rad/s`，最大绝对roll/pitch约 `5.95e-6/1.12e-5rad`；高档yaw总变化很小，不能用持续大角速度或可见倾斜解释约 `.111rad` 方向差。首转静稳10Hz跨度约1秒，yaw几乎不变，不能仅靠延长静稳或缩小初转`.025`接纳窗解决主要偏差。

源码只读交叉复核由控制审查代理完成：实际adapter构造 `Twist` 后仅写 `linear.x` 与 `angular.z`，其余字段默认0；没有根据yaw转换world XY、没有linear.y伺服或轨迹重标。公开候选world仅含mecanum/UAV插件配置，未提供能直接确认现行平台坐标语义的插件源码。未读取裁判私有数据或二进制以推断接口。

## 对下一步修复的约束

当前可以确定的代码假设缺口是：**路线把 `linear.x>0, angular.z=0` 当成位移必沿收到的body yaw，但真实非零yaw直行尚不支持这个假设。** 直接放宽`.02m`横偏、`.05rad`heading或继续盲走，会掩盖该不一致；不能作为修复。也不应只补初转角度而宣称已经解决。

若主代理采用 `ground_4` 的X轴候选观察位，这只绕开当前单点的斜向直行假设，并提供下一次可测观察机会；仍不能证明其他朝向/路径可控。通用路线要通过后续有限、闭环、有原始世界位移证据的方向响应测试，或取得现行公开接口坐标合同，才能确定如何变换/补偿。此审查没有新增控制命令。
